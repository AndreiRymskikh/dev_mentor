<h2>1. Purpose</h2>
<p>Connect a control’s visible label, requirement state, guidance and error without repeating accessibility wiring.</p>
<Source ids="AUTH shared field state; F02–F04/F07; TASK forms; WCAG 1.3.1, 3.3.1, 3.3.2, 4.1.3" />
<h2>2. When to use</h2>
<p>Use around Input or Textarea in authentication, availability and eventual feedback forms. The render callback receives the shared control attributes, so both control types keep their real package implementation.</p>
<Source ids="AUTH shared field state; F02–F04/F07; TASK forms; WCAG 1.3.1, 3.3.1, 3.3.2, 4.1.3" />
<h2>3. When not to use</h2>
<p>It is not a form builder, validator, server adapter or success notifier. Do not replace the existing CrudForm API with it. Do not use it as a choice-group fieldset or add checkbox/select controls before their approved batches.</p>
<Source ids="AUTH shared field state; F02–F04/F07; TASK forms; WCAG 1.3.1, 3.3.1, 3.3.2, 4.1.3" />
<h2>4. Anatomy</h2>
<p>A field group contains Label, visible Required/Optional wording, an optional hint, the render-callback control, optional icon-and-text error, and an optional disabled reason. IDs are generated unless a stable id is supplied. Descriptions are combined in hint, error, reason order.</p>
<Source ids="AUTH shared field state; F02–F04/F07; TASK forms; WCAG 1.3.1, 3.3.1, 3.3.2, 4.1.3" />
<h2>5. Variants and sizes</h2>
<p>There are no visual variants. Required and optional are semantic field requirements; enabled, disabled and error are data states. Native control styling comes from Input or Textarea. Fields are intended on page or card surfaces; do not place their muted helper text directly on the support or inverse surface.</p>
<Source ids="AUTH shared field state; F02–F04/F07; TASK forms; WCAG 1.3.1, 3.3.1, 3.3.2, 4.1.3" />
<Canvas of={Stories.RequiredAndOptional} />
<h2>6. States</h2>
<p>Default, hover and focus are demonstrated through the contained native control. An error adds aria-invalid, a linked error message and an alert icon with words. Disabled adds native disabled and a visible reason. Required/Optional text stays visible. Loading belongs to the form action; pressed and selected belong to buttons or choice controls, not to FormField itself.</p>
<Source ids="AUTH shared field state; F02–F04/F07; TASK forms; WCAG 1.3.1, 3.3.1, 3.3.2, 4.1.3" />
<Canvas of={Stories.States} />
<h2>7. Behavior and accessibility</h2>
<p>Spread the callback attributes onto exactly one real control. The label points to that id; hints, errors and disabled explanations are connected through aria-describedby. Error changes use role=alert. The owner validates on blur and submit, focuses the first invalid control after a failed submission, preserves entered data, prevents duplicate requests and only reports success after server confirmation. The interaction story demonstrates owner-supplied feedback; FormField does not silently validate or submit. WCAG: 1.3.1 (relationships), 2.1.1 (keyboard), 2.4.7 (focus), 2.5.8 (target size), 3.3.1/3.3.2 (errors and labels), 4.1.2/4.1.3 (name/state and announcements).</p>
<Source ids="AUTH shared field state; F02–F04/F07; TASK forms; WCAG 1.3.1, 3.3.1, 3.3.2, 4.1.3" />
<h2>8. Content</h2>
<p>Use a familiar label, a hint explaining an actual constraint, and an error that says what happened and how to correct it. Disabled reasons must explain the real eligibility rule. Do not infer public ratings, a service-completion marker or a feedback length from this example. Long messages wrap without truncation; identifiers remain stable through updates.</p>
<Source ids="AUTH shared field state; F02–F04/F07; TASK forms; WCAG 1.3.1, 3.3.1, 3.3.2, 4.1.3" />
<h2>9. Responsiveness</h2>
<p>Verify at 320, 768 and 1440px in both themes. Preserve the source order, wrap labels and feedback, and keep the approved minimum target height rather than shrinking type. Use semantic group/panel spacing and a readable body measure. The narrow story is a fluid maximum-width specimen; it must not force horizontal page overflow. [F02/F03/F06; WCAG 1.4.10]</p>
