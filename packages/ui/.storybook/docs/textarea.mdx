<h2>1. Purpose</h2>
<p>Let a developer write a multiline explanation or post-service feedback.</p>
<Source ids="BRIEF D03/D04; AUTH shared field state; F02–F04; TASK forms" />
<h2>2. When to use</h2>
<p>Use for free-form multiline text such as feedback after the service. Compose with FormField and provide enough context for the developer to know what to write.</p>
<Source ids="BRIEF D03/D04; AUTH shared field state; F02–F04; TASK forms" />
<h2>3. When not to use</h2>
<p>Use Input for an email, password or a short single-line value. Do not introduce an editor toolbar, Markdown editor or session chat in this batch. The product’s text session itself remains external.</p>
<Source ids="BRIEF D03/D04; AUTH shared field state; F02–F04; TASK forms" />
<h2>4. Anatomy</h2>
<p>A native multiline textarea has its own editable value and vertical resize handle. FormField provides the visible label, hint, requirement state, error and optional disabled reason.</p>
<Source ids="BRIEF D03/D04; AUTH shared field state; F02–F04; TASK forms" />
<h2>5. Variants and sizes</h2>
<p>One approved style: a minimum height of 128px, 8px radius, body typography, and token-based padding. There is no compact textarea variant. Height may grow through vertical resizing; horizontal page overflow is not introduced.</p>
<Source ids="BRIEF D03/D04; AUTH shared field state; F02–F04; TASK forms" />
<Canvas of={Stories.Playground} />
<h2>6. States</h2>
<p>Default, hover, focus, disabled, read-only and error are demonstrated. Read-only preserves copying. A disabled feedback example explains that the service has not occurred; it does not implement a completion policy. Native text selection is available; pressed/selected do not have independent component styling. Loading is an action/form concern and must retain entered text.</p>
<Source ids="BRIEF D03/D04; AUTH shared field state; F02–F04; TASK forms" />
<Canvas of={Stories.States} />
<h2>7. Behavior and accessibility</h2>
<p>Use native multiline keyboard behavior. Enter inserts a newline rather than submitting. Preserve the value after failed validation or a server error. The owner validates on blur/submit and supplies FormField error text. Keep focus visible, labels associated and errors described. Vertical resizing stays enabled. WCAG: 1.3.1 (relationships), 2.1.1 (keyboard), 2.4.7 (focus), 2.5.8 (target size), 3.3.1/3.3.2 (errors and labels), 4.1.2/4.1.3 (name/state and announcements).</p>
<Source ids="BRIEF D03/D04; AUTH shared field state; F02–F04; TASK forms" />
<h2>8. Content</h2>
<p>Ask a concrete question, such as Which explanation helped you move forward? Avoid suggesting that feedback is a public rating. No default maximum length is imposed. The 500-character story limit is an illustrative native constraint, not approved feedback policy. Wrap long labels and messages, and test a longer translation without clipping.</p>
<Source ids="BRIEF D03/D04; AUTH shared field state; F02–F04; TASK forms" />
<h2>9. Responsiveness</h2>
<p>Verify at 320, 768 and 1440px in both themes. Preserve the source order, wrap labels and feedback, and keep the approved minimum target height rather than shrinking type. Use semantic group/panel spacing and a readable body measure. The narrow story is a fluid maximum-width specimen; it must not force horizontal page overflow. [F02/F03/F06; WCAG 1.4.10]</p>
