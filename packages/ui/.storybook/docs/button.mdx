<h2>1. Purpose</h2>
<p>Let a developer perform an action such as requesting a session or submitting credentials.</p>
<Source ids="A1; F02–F04/F08; AUTH; BRIEF D04; TASK Stage 2" />
<h2>2. When to use</h2>
<p>Use primary for the main action in a group, including Request session and Sign in. Use text for a lower-emphasis action such as Clear search. Use a native submit button only when it belongs to a form.</p>
<Source ids="A1; F02–F04/F08; AUTH; BRIEF D04; TASK Stage 2" />
<h2>3. When not to use</h2>
<p>For navigation to a mentor profile, public work or password recovery, use Link. Do not add destructive, ghost, secondary or oversized variants from the base library: they are not part of this approved batch.</p>
<Source ids="A1; F02–F04/F08; AUTH; BRIEF D04; TASK Stage 2" />
<h2>4. Anatomy</h2>
<p>An inline action wrapper contains the native button and, when needed, a visible progress status or unavailability explanation. The button contains its retained action label and an optional supporting icon. An icon-only button requires aria-label.</p>
<Source ids="A1; F02–F04/F08; AUTH; BRIEF D04; TASK Stage 2" />
<h2>5. Variants and sizes</h2>
<p>Primary and text are the only variants. Default controls have a 48px minimum height; compact controls have a 40px minimum height and are reserved for dense administrative rows. Icon actions are 40px square. Use the standard size on booking and authentication screens.</p>
<Source ids="A1; F02–F04/F08; AUTH; BRIEF D04; TASK Stage 2" />
<Canvas of={Stories.VariantsAndSizes} />
<h2>6. States</h2>
<p>Default, hover, focus-visible and pressed are shown in the matrix. Frozen hover/focus reuse the same CSS utilities as live states. Disabled blocks activation and needs a visible reason; loading blocks repeat activation, retains the label, sets aria-busy and announces In progress. Selected is available only for a real toggle via aria-pressed; an ordinary booking action is not a toggle. An action error appears outside the button with a corrective next step.</p>
<Source ids="A1; F02–F04/F08; AUTH; BRIEF D04; TASK Stage 2" />
<Canvas of={Stories.States} />
<h2>7. Behavior and accessibility</h2>
<p>Native buttons activate with Enter or Space and follow DOM focus order. The default type is button to avoid accidental submission; use type=submit intentionally. Native disabled and busy buttons are skipped in the tab order; disabledReason stays visible and is associated through aria-describedby. Keep a corrective error near the action. Focus is a 2px outline with a 4px surface offset. Targets meet the approved 40/48px sizes, above the WCAG 24px minimum. WCAG: 1.3.1 (relationships), 2.1.1 (keyboard), 2.4.7 (focus), 2.5.8 (target size), 3.3.1/3.3.2 (errors and labels), 4.1.2/4.1.3 (name/state and announcements).</p>
<Source ids="A1; F02–F04/F08; AUTH; BRIEF D04; TASK Stage 2" />
<h2>8. Content</h2>
<p>Use a verb and object: Request session or Save availability, not OK. Do not invent a response-time promise. Keep the label while pending. There is no hard character limit: long and translated labels wrap and increase height. For an icon action, supply its full purpose in aria-label.</p>
<Source ids="A1; F02–F04/F08; AUTH; BRIEF D04; TASK Stage 2" />
<h2>9. Responsiveness</h2>
<p>Verify at 320, 768 and 1440px in both themes. Preserve the source order, wrap labels and feedback, and keep the approved minimum target height rather than shrinking type. Use semantic group/panel spacing and a readable body measure. The narrow story is a fluid maximum-width specimen; it must not force horizontal page overflow. [F02/F03/F06; WCAG 1.4.10]</p>
