## Finding — P2: preserve malformed money configuration across dotenv publication

`scripts/setup/runtime.mjs:64` places `PLATFORM_PRICE_BOUNDS` inside literal single quotes without handling a single quote in the supplied value. Reproduction: pass the valid approved bounds JSON followed by one apostrophe through the process override into fresh setup. `readPricePolicy` rejects that original value with 503. `publishEnvironment` writes the value inside another pair of single quotes; Node `parseEnv` truncates at the embedded apostrophe, so reopening the published `.env` yields the valid JSON with the erroneous trailing character removed. `readPricePolicy` now accepts it. Thus a malformed policy can become enabled after restart rather than fail closed. Confirmed with real temporary files, actual setup writer, actual parser and actual policy resolver; no developer configuration modified.

Reject malformed money configuration before publication or use a proven lossless dotenv encoding and round-trip validation. Add a regression proving malformed values containing the quote delimiter cannot become accepted policy after file write/reload. This is a money-policy configuration correctness issue, not an untrusted remote-input exploit.
